# Product specification — v2.4 (coarse indexes in JSON, heavy layers in the light GPKG, NE cells)

`v21_products.PRODUCT_VERSION = "2.4"`, `MANIFEST_VERSION = "v2.4"`. Load
when touching `v21_products.py`, the `v21` plumbing in
`austria_processor.py`, `v2_verify.py`, `kg_v2_store.py`, `v2_ingest.py`,
`v24_fast.py`, `app._grid25_for_kg` / `_heightfield_from_grid25`, or
`/api/v3/trees` (`docs/tree-inventory-v3.md`). NE cell records:
`docs/ne-v24-design.md`.

## 1 · Product set per code

Codes are product codes: a parent KG (`61047`) or a split block
(`04016-southwest`, `docs/austria-processor.md` → *KG block splitting*).

| manifest key | file | notes |
|---|---|---|
| `_full_gpkg` | `<code>_full.gpkg` | fresh runs only; ~22 layers incl. every input raster, `segments` (EPSG:3035, 55 properties) and `segment_points` (EPSG:4326, 54). Input of every later upgrade. |
| `_light_gpkg_v2` | `<code>_light_v2.gpkg` | `segments`, `segment_points`, `segment_type`, `segment_height`, `new_buildings`, `infrastructure`, `tree_apices` (+ R-tree), `tree_crowns`, `terrain_coarse_{dtm,dsm,ndsm,slope,aspect}`; `layer_styles` row per layer. No footprint-shaped layers (`v2_verify.FORBIDDEN_LIGHT_LAYERS`). |
| `_ne_h3b` | `<code>_ne.h3b` | NE cells (H3) container — `docs/ne-v24-design.md`. |
| `_json_v2` | `<code>_v2.json.gz` | `kgjson/2` (`kg_json_v2.py`), lossless, 18–22× smaller than v1 JSON; ingested into `kg_v2_store`. |
| `_json` | `<code>.json` | the **completion marker** (coverage oracle, queue pruning, index); never rename. |

Upload order: full → light_v2 → ne_h3b → json_v2 → json (the marker goes
last). Manifest record `status` vocabulary (`zenodo_client.Entry`): `cf`
(written by 2.4+ code), `stripped` (older `_json` re-PUT without retired
sections), `removed` (deposition deleted, record kept with `size: 0` —
read as absent everywhere; the coverage oracle ignores it). A legacy
`_light_gpkg` (pre-2.4) is removed, never served.

A JSON product missing a cache-fillable layer carries
`version: "v2.4-partial"` (`docs/product-repair.md`); missing NE cells →
defect `ne_cells`.

### Quick GPKG validity check

```bash
sqlite3 f.gpkg 'PRAGMA integrity_check; PRAGMA foreign_key_check; PRAGMA application_id'   # ok / (none) / 1196444487 (GPKG)
sqlite3 f.gpkg 'SELECT table_name, data_type, srs_id FROM gpkg_contents'
sqlite3 f.gpkg 'SELECT COUNT(*) FROM layer_styles'          # == number of layers
sqlite3 f.gpkg 'PRAGMA table_info(segments)' | wc -l         # 55 (+ fid/geom) ; segment_points 54
```

## 2 · Disk rule (hard)

Per-tree / per-pixel / per-5 m data → `_light_v2.gpkg` on Zenodo only.
JSON + `kg_v2_store` get fixed-size 25 m indexes, ≤ 25 KB per KG. No
per-tree rows in `search_index.db`, no polygons in JSON.

## 3 · Where things live

| piece | code |

## 4 · Formats

**`terrain.grid25`**: `{cell_m: 25, cols, rows, origin: "nw", crs: "EPSG:3035",
x0, y0, unit: "dm", base_dm, coding: "delta_i16" | "i32", elev: <b64 gz>,
valid?: <b64 gz packbits>, slope: <b64 gz uint8 deg, 255 nodata>, n_valid}`.
The grid is the union of the 25 m-snapped (bbox-overshooting) tile
rectangles, so it *covers* the bbox with ≤ 1.7 km slack per side. Decode:
`v21_products.decode_terrain_grid25`.

**`landcover.grid25`**: same grid; `coding: "u8"`, `cls` (uint8 type code,
0 = none), `cover_frac` (0..255), `woody_frac`, `tree_frac`, `canopy_frac`
(apex-inventory canopy mask), `legend: {code: type}`, `n_classified`.
Decode: `decode_landcover_grid25`.

**`acquisition`**: `{tiles: [{tile, dtm_year, dsm_year, ortho_year,
eff_date, years_gap}], summary: {n_tiles, n_known, als_year_min/max,
years_gap_median, source}}` (flight blocks from
`data/als_acquisition/*.geojson`, `als_acquisition.py`).

**Robust top-N ranking** (`top_10_objects`, `top_10_trees`,
`top_manmade_objects`, `top_by_type`): ranking metric `height_robust_m =
min(height_max_m, height_p90_m + 10)` (`_robust_height`,
`ROBUST_HEIGHT_MARGIN_M`) so single-pixel DSM spikes collapse to the
canopy; `height_m` in the rows is the robust height, raw stays in
`height_max_m`. Plausibility gate before top-N (`_top_quality`):
`quality_flags.apply_rules` on the robust height — any height-family flag
≥ `high` excludes (`*_height_implausible`, `flat_type_has_height`,
`water_has_height`, `mast_likely_misclassified`), plus `critical` on raw
hmax. Surviving codes ride in each row's `quality_flags`; the
`top_ranking` block documents metric + `quality_flags.RULE_VERSION`.

**`_light_v2.gpkg`**: `tree_apices` points EPSG:3035 + R-tree, columns
`tree_id, h_m, crown_r_m, crown_area_m2, detection_source, detection_conf,
surface_class, tree_likelihood, stand_context (tree/orchard/vineyard/hedge/
garden/shrub/other/none), segment_type, segment_type_conf, dh_per_year_m,
als_year, ndvi_mean, ndvi_p10, nir_mean, brightness_mean,
green_ratio_mean, vitality, vitality_conf, species_hint, species_conf,
leaf_type_hint, leaf_type_conf, dbh_est_cm, volume_m3_est`;
`tree_crowns` polygons (`tree_id` only, simplified 0.5 m, no R-tree);
`terrain_coarse_{dtm,dsm,ndsm,slope,aspect}` single-band **float32** 5 m
(m / deg, nodata −9999 — int16 dropped: GDAL reads Int16 GPKG coverage
nodata back as +32768).

**Grid anchor**: `raster_io.read_window_bbox` snaps bboxes outwards to
whole metres → every 1 m grid is the integer-metre EPSG:3035 BEV grid,
apex = pixel centre, `tree_id = t_<E_dm>_<N_dm>` identical product ↔ live.
`v2_source._Gpkg` re-anchors v1 GPKG transforms (`floor(c)`, `ceil(f)`).
Test: `tests/test_grid_anchor.py`.

Apex inventory: `tree_inventory.build_inventory` **ndsm_only** on the
stitched nDSM (only where a segment exists), 2048 px chunks + 48 px halo
(apex-in-core); optional `building_mask` from the BEV vector-tile
context when `SRTM_BEV_VECTOR_CONTEXT=1` (`docs/vct-pilot.md`). No fused
mode in the processor (fused seeding needs ≤ 0.5 m ortho).

## 5 · Verify checks (`v2_verify`)

`product_version` (fatal) · `grid25_present` (warn — huge KGs) ·
`grid25_decodes`, `grid25_dims` (covers bbox, ≤ 1.7 km slack),
`grid25_finite` (≥ 40 % cells), `grid25_range` (±50 m fatal, ±5 m drift
warn), `landcover_grid25_dims` · `tree_stats_v21` (warn) ·
`terrain_coarse_layers` (fatal iff grid25 present) · `apices_layer`
(fatal iff JSON claims it; count ±20 %, R-tree) · `apex_grid_anchor`
(warn) · `crowns_layer` (warn) · `check_v23_top_ranking` (every top row
`height_robust_m ≤ height_max_m`, sorted, no tree ≥ 80 m / ground ≥ 5 m
/ water ≥ 5 m robust) · `segments_label_consistency`
(`docs/label-mix.md`) · light GPKG forbidden layers · `ne_h3b_valid`,
`ne_observed_digest`, `ne_cells_observed`, `ne_algo`. Tests:
`tests/test_v22_product.py`, `tests/test_v23_top_ranking.py`.

## 6 · Upgrading older products in place

A code whose `_full_gpkg` is committed but whose `_json_v2` is not on the
current version is an **upgrade unit** (`v2_upgrade_eligible`: `_json` +
committed `_full_gpkg`, no current `_json_v2`, < 2 strikes in
`v2_upgrade_failed.json`). The director appends such units to the queue
when fresh cache-ready work runs low (`_v2_upgrade_fill`); the processor
runs them with `--cache-only --v2-upgrade`:

1. `_v2_fetch_inputs` — v1 JSON (bbox + verify baseline) and the full GPKG
   into `data/austria_processor/v2_source/` (md5-checked);
2. `process_one_kg(source_gpkg=…, v1_doc=…)` — the `v2_source` shim
   replaces BEV reads, no new full GPKG; writes `_light_v2.gpkg`,
   `_ne.h3b`, `_v2.json.gz`;
3. `v2_verify.verify_before_upload` → FAIL = `aborted_v2_verify_failed`
   (files deleted, strike, no `failed_kgs` entry); PASS = ordered upload
   light_v2 → ne_h3b → json_v2 under the Zenodo lock. Source GPKG deleted
   afterwards; `progress.v2_upgraded` counts; log prefix `v2up:`.

**Fast path** (`v24_fast.py`): a code already on ≥ 2.3 is relabelled to
2.4 from its `light_v2` + `json_v2` in seconds (no tile loop) unless the
light GPKG fails the label-mix gate (`v24_fast_declined`).

`MODEL_VERSION` defaults to v2 iff `segv2.model_v2.available()` (lightgbm
importable + `data/segv2/models/model_G.joblib` present —
`tools/fetch_models.py`); otherwise the RF v1 classifier runs.

**Never** use `POST /processing/queue {skip_processed: false}` to get a
v1-complete KG onto the current version: that path tombstones every
product pointer including `_full_gpkg`, so the code stops being an
upgrade candidate and becomes a from-scratch rerun that needs BEV +
Copernicus. Reprocess an upgrade by dropping `<code>_json_v2` +
`<code>_light_gpkg_v2` from the manifest instead.

## 7 · Ingest on the serving side (`v2_ingest.py`)

Daemon thread in `app.py` (`_v2_ingest_thread`, fcntl single-flight
across gunicorn workers, 5-min tick, ≤ 20 codes per tick, `V2_INGEST=0|1`
override). Per code: download (+ size / md5 check) → `verify_for_ingest`
→ `store.put` **first** → `search_index.update_kg` → delete
`json/<code>.json` → `quality_flags.scan_doc`; then
`kg_log_harvest.harvest_live()`. Failures: `meta.ingest_failed`
`{code: {n, reason, uploaded_at}}`, 3 strikes per upload (a newer upload
resets). NE cells are pulled separately by `ne_ingest`
(`docs/ne-public-api.md`).

Telemetry: `search_index.progress_summary(manifest)` is the source of
truth for every progress indicator (`versions:` / `v2:` lines on
`/process.txt`, `/api/v1/processing/status`).

```bash
python3 v2_ingest.py status                 # v2: line + JSON
python3 v2_ingest.py                        # one ingest tick now
python3 v2_ingest.py 19570                  # dry ingest one code (no delete / index / flags)
python3 kg_log_harvest.py 19570             # targeted history fold + last rows
curl -s 'localhost:8000/api/v1/kg/19570?history=1' | jq '.history[-5:]'
```

Re-ingest a code: `kg_v2_store.delete(code)` — the next tick re-downloads.

## 8 · Invariants

* `_json` stays the completion marker; upgrades never touch `_json` /
  `_full_gpkg`.
* `store.put` before `update_kg` before deleting the v1 file (the loader
  reads the store first).
* `-partial` is only ever appended to a JSON product's `version`.
* Tree ids are grid-anchored; any change to the 1 m grid origin is a
  product-version bump.
